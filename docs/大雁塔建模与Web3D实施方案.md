材质方向：灰褐与暖赭之间的旧砖、较深的潮痕、适量修补色差；颜色以多张正常日光照片核准。磨损集中在棱角、檐口、雨水路径等合理部位。风化强度作为参数，避免把全部墙面做成破败废墟。

## 4. GPT-6 + Blender 制作流程

### 4.1 工作分工

GPT-6 整理证据、参数和脚本，调用 MCP 执行分阶段操作并检查反馈。Blender 承担几何、修改器、材质、UV、烘焙、渲染、源文件保存与 glTF 导出。网页通过 Three.js 加载最终 GLB 并提供交互。

整个流程是单一可复现的脚本项目。每个阶段保存文件和运行日志，固定随机种子，允许重做某一层或某套材质。MCP 每次只执行可检查的工作块，避免一次执行全部建模和长时间烘焙。

### 4.2 小样先行

先制作一段带砖柱、拱券、檐口的试验墙，完成：Blender 材质 → UV → 贴图烘焙 → GLB 导出 → Three.js 加载。验证单位、朝向、法线方向、色彩、阴影和构件属性；通过后将同一流程扩展到整塔。

### 4.3 白模与结构

建立平台、七层主体、主要洞口和塔刹白模。用四立面与斜视对照图验证总体比例。楼层参数不能用同一倍率递缩替代实证校准。

结构阶段先完成真实空腔，再添加檐口和材质；为楼梯预留楼板开口。每层主体下按四立面分组，内构单独归组，以便隐藏墙面和查看空间。

### 4.4 高精度源模型与网页模型

Blender 源模型保留可编辑修改器、重复构件、细部源网格及完整贴图。导出副本按构件材质适度合并，清理不可见面和退化面，减少节点与绘制次数。

合并边界服从交互：不跨楼层、可隐藏立面或独立热点对象合并。建立 Empty 父节点和自定义属性，例如 `floor`、`facade`、`componentType`、`evidenceLevel`、`sourceId`。不能假定 Blender Collection 自动完整映射成 GLB 层级。

建议层级：`DayanPagoda / Platform / Floor01...Floor07 / Crown / Finial`；楼层下设 `FacadeN/S/E/W`、`Eaves`、`Interior`、`Stairs` 等节点。导出后自动检查节点契约。

### 4.5 材质与导出

程序材质烘焙成 Base Color、Normal、AO、Roughness 等可移植贴图，按 glTF 通道组织 ORM。基础贴图建议 2K，石刻近景和重点构件按需 4K。大面积砖墙使用可平铺细节配合独特的色差、污迹遮罩，避免一张低分辨率图覆盖整塔。

Blender 的节点材质不能保证原样转换为网页材质，应按其[官方 glTF 导出说明](https://docs.blender.org/manual/en/4.0/addons/import_export/scene_gltf2.html)支持的结构输出；具体接口需匹配本机版本。照明不烘死在 Base Color 中，以便昼夜切换；AO 强度需防止与实时阴影重复叠黑。

保留原始导出文件，再使用 glTF-Transform / Meshopt 生成发布版本。KTX2 为通过兼容性小样后的纹理优化项，转换工具不可用时用标准图片格式交付，并如实记录性能。

## 5. 网页与交互方案

### 5.1 页面风格

延用暖纸底 `#f6f2eb`、墨灰字 `#302f2b`、朱砂红 `#ae3625` 和细分隔线。宋体用于建筑名称，清楚的无衬线字用于操作。塔体灰褐材质通过侧光与暗部从背景中分离。

顶部：雁塔印记、西安大雁塔、建筑概览、专注浏览、建模说明。

左侧：中文名称、GIANT WILD GOOSE PAGODA、始建 652 年、现存七层、简短介绍、约值尺度与“探索塔身”按钮。补充轻量的玄奘与藏经背景。

中央：完整实时模型，首屏采用能同时看清南面碑龛与侧面层次的斜视。塔高约占可用画布高度的 80%—88%，以不同屏幕实测校准。采用较小透视夸张，保持挺拔和稳重。

右侧：楼层选择、外墙显示、内部结构、尺寸、分层展开、结构剖视、夜间灯光。低频操作可折叠，首屏保持轻量。

底部：视角缩略图、缩放、完整入画、复位、自动旋转。继续使用独立工具栏占位，防止挡住平台和模型底部。

### 5.2 预设视角

计划提供全景、南立面、东立面、北立面、西立面、俯视、首层入口、南面碑龛、石门楣、檐口近景、塔刹、首层塔室、木梯、顶层塔室、剖面总览。首屏仅展示最常用四项，其余展开。

视角配置包含 position、target、适用构件可见性、说明与证据等级。网页缩略图从最终模型同一相机配置生成。内部使用受控视角与点位切换，避免相机过渡穿过实体墙。

### 5.3 结构探索

- 楼层选择：点击 1—7 层，定位并高亮该层，显示对应构件说明。
- 分层展开：保存每层初始矩阵，以统一展开参数增加竖向间距；塔刹跟随顶层。恢复时精确回到原位。
- 内部结构：按方向隐藏指定外墙，展示中央塔室、楼板和楼梯。
- 剖视：优先用预制带封口的剖视网格，或验证后的裁切封口方案；不能仅裁掉表面后暴露空壳。剖切纹理属于展示辅助。
- 证据说明：热点说明中区分可靠资料和空间示意，不在主界面堆满技术参数。

展开与剖视先做互斥状态，切换时归位。展开后相机重新计算包围盒，热点和尺寸标签跟随楼层。结构示意状态显示短标签，避免被理解为真实拆解方式。

### 5.4 灯光与响应式

日景用柔和环境光、侧向主光及适量补光表现砖面。夜景用暖色建筑洗墙光与较暗背景，保留材质层次。页面夜景为展示性灯光方案，不标为现场照明测绘。

模型画布透明，与页面背景连续；地面只接收柔和阴影。桌面保留三栏，窄屏将介绍压缩、控制折叠，视角栏横向滚动。浏览器无 WebGL 或加载失败时显示同模型静态图和重试入口。

旋转默认关闭，支持键盘操作、清楚的焦点状态及 reduced-motion。切换视角、复位、展开和加载错误状态必须可恢复。

## 6. 性能预算与质量验收

以下均为设计目标，尚未实测。通过材质和关键几何提高精细度，而非统一增加面数。

| 指标 | 初始目标 |
| --- | --- |
| 标准网页模型 | 约 30 万—60 万三角面 |
| 高清网页版本 | 约 80 万—150 万三角面，按实际收益调整 |
| 移动简化版本 | 约 12 万—25 万三角面 |
| 标准模型传输体积 | 目标 15—25 MB；首页优先显示轻量预览 |
| 高清模型体积 | 目标 25—45 MB，用户切换后按需加载 |
| 标准模式可见绘制调用 | 尽量不超过 150，阴影和剖视另行统计 |
| 桌面帧率 | 明确设备、浏览器、1080p 和像素比后，以 50—60 FPS 为目标 |
| 移动帧率 | 在明确测试设备与画质下争取稳定 30 FPS；未真机测试不得声称已达标 |

同一时刻保留一套主体模型，切换后释放旧 GPU 资源。限制像素比、阴影分辨率和后处理，后台暂停渲染。下载体积、解压后纹理占用、显存峰值分别记录。

几何验收：七层、立面分格、主要洞口及碑龛关系正确；标高闭合；无明显穿插、悬空、漏面、退化三角面和法线错误。墙体切口和剖面封口正确；楼梯不撞楼板，楼板开口连贯。

视觉验收：四立面、两斜角、俯视、檐口、入口、石刻、塔刹及内部固定相机截图；与对应参考比较轮廓和细节；统一曝光下检查 Blender 与网页材质差异。日夜、标准高清均检查。

网页验收：加载、错误重试、所有视角、隐藏构件、楼层选择、展开归位、剖视切换、尺寸标签、夜景、自动旋转、专注浏览、窗口缩放、键盘操作、静态降级和二级路径资源加载。

工程验收：`npm run check`、`npm run build`；glTF Validator 零错误，警告逐条消除或说明；模型节点元数据保留；源工程可重新打开；脚本可在文档化环境内重建。记录真实测试配置和结果，不以预算替代实测。
